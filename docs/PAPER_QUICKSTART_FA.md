# شروع Paper Trading روی مک

این فرمان از دادهٔ عمومی واقعی BIP/M15 استفاده می‌کند؛ حساب، سفارش و پول همگی
فرضی‌اند. حساب Coinbase، کلید API و دسترسی معامله لازم نیست.

در Terminal، داخل پروژه و با محیط مجازی فعال:

```bash
git switch main
git pull origin main
python3 -m pip install -e .
python3 -m metatr.paper_setup \
  --workspace "$HOME/metatr-state/paper-bip" \
  --start --confirm-paper
```

در اولین اجرا، کندل‌ها و مشخصات بومی قرارداد دریافت و اعتبارسنجی می‌شوند؛
دیتابیس بازار، رجیستری Momentum 1.0.0، حساب Paper و چهار فایل تنظیمات ساخته
می‌شوند. سپس برنامه هر ۳۰ ثانیه بررسی می‌کند. داده‌های قبلی برای گرم‌شدن مدل
استفاده می‌شوند؛ سفارش تاریخی ساختگی ایجاد نمی‌شود. پرشدن فرضی زودتر از
بسته‌شدن کندل بعدی ثبت نمی‌شود.

ترمینال را باز نگه دارید. با `Control+C` برنامه متوقف می‌شود. همین فرمان برای
ادامهٔ حساب موجود است؛ تنظیمات و موجودی قبلی بازنویسی یا HALT پاک نمی‌شوند.
برای اجرا بدون شروع حلقه، `--start --confirm-paper` را حذف کنید.

## مشخصات سناریو

| تنظیم | مقدار |
| --- | --- |
| بازار | `coinbase:BTC:FUTURE:BIP-20DEC30-CDE:M15` |
| حساب | `bip-paper` |
| سرمایهٔ فرضی | ۱۰٬۰۰۰ دلار |
| هدف موقعیت | یک قرارداد؛ حداکثر یک قرارداد باز |
| سقف ارزش موقعیت | ۲٬۰۰۰ دلار؛ سقف سفارش معکوس ۴٬۰۰۰ دلار |
| سقف اهرم فرضی | ۱؛ بدون مدل مارجین یا لیکوییدیشن واقعی |
| توقف زیان روزانه | ۱۰۰ دلار |
| توقف افت سرمایه | ۵٪ |
| دادهٔ کهنه | حداکثر دو کندل |
| کارمزد فرضی | ۱۰ basis point، برابر ۰٫۱٪ ارزش معامله، برای هر سمت |
| اسپرد و لغزش فرضی | اسپرد کامل ۲ basis point و یک tick لغزش |
| تأمین مالی فرضی | هزینهٔ مطلق ۰٫۰۱ basis point در هر کندل M15 |
| حجم | سناریوی فرضیِ حجم بر حسب قرارداد؛ سقف مشارکت ۱۰٪ |

این اعداد، سناریوی مهندسی برای Paper هستند و ادعای تعرفه یا شرایط واقعی صرافی
نیستند. اندازه، حداقل تعداد و گام قیمت قرارداد از پاسخ عمومی همان محصول خوانده
و هش می‌شوند. تغییر قیمت، حجم روزانه یا نرخ funding هویت قرارداد را عوض نمی‌کند؛
تغییر مشخصات ساختاری باید رد شود. پاسخ خام کامل همچنان در دیتابیس محفوظ است.

## تقویم و توقف

`setup.json` زمان `session_coverage_end_utc` را نشان می‌دهد. تقویم صرفاً بازهٔ
جلسهٔ بازِ تأییدشده در API و پنجرهٔ نگهداری اعلام‌شدهٔ آن است. پایان این پوشش،
بسته‌شدن جلسه، خطای منبع یا مشخصات ناسازگار باعث توقف می‌شود. این راه‌اندازی
به‌تنهایی تأیید اجرای ۱۴روزه نیست؛ جلسات آینده به تقویم تأییدشده نیاز دارند.

از `--start` برای پاک‌کردن توقف استفاده نشود. مسیر بازنشانی همراه با دلیل و
بررسی سلامت تازه در [PAPER_OPERATIONS.md](PAPER_OPERATIONS.md) آمده است؛
ساخت حساب جدید جای بررسی علت توقف حساب قبلی را نمی‌گیرد.

## وضعیت و گزارش

در یک Terminal دیگر:

```bash
python3 -m metatr.paper_setup --workspace "$HOME/metatr-state/paper-bip" --status
python3 -m metatr.paper_setup --workspace "$HOME/metatr-state/paper-bip" --report
```

گزارش JSON در پوشهٔ `reports` همان workspace ذخیره می‌شود. دفتر رخداد، تنظیمات،
قیمت‌های خام و گزارش‌ها به گیت ارسال نمی‌شوند. workspace مستقل از checkout است.
قبل از انتقال یا پشتیبان‌گیری از SQLite، برنامه را متوقف کنید و از روش SQLite
backup در راهنمای عملیات استفاده کنید.

برای نمایش اختیاری سیگنال Paper در MT5، هنگام شروع اضافه کنید:

```bash
--display-output-dir "$HOME/Library/Application Support/net.metaquotes.wine.metatrader5/drive_c/users/user/AppData/Roaming/MetaQuotes/Terminal/Common/Files"
```

نمایشگر باید قبلاً روی چارت متصل باشد؛ MT5 فقط نمایش می‌دهد و اجرای سفارش ندارد.
این برنامه foreground است؛ سرویس دائمی macOS نصب نمی‌کند و روی مک شما از راه
دور اجرا نمی‌شود.

منبع مشخصات بومی: پاسخ عمومی
`https://api.coinbase.com/api/v3/brokerage/market/products/BIP-20DEC30-CDE`.
مرجع توضیح قرارداد: [Coinbase contract specifications](https://help.coinbase.com/en/derivatives/perpetual-style-futures/contract-specifications).
پنجرهٔ جلسه و تعمیرات از API می‌آید؛ از توضیحات عمومی، تعطیلات آینده استنتاج نمی‌شود.

## ثبت شواهد پایش و پشتیبان‌گیری

برای ذخیرهٔ وضعیت واقعیِ همین لحظه در کنار بررسی سلامت دفتر حساب Paper، از
فرمان زیر استفاده کنید:

```bash
python3 -m metatr.paper_observe \
  --workspace "$HOME/metatr-state/paper-bip" \
  --backup --require-healthy
```

هر اجرا یک سند JSON تغییرناپذیر شامل زمان UTC، هش زنجیرهٔ رخدادها، موجودی
فرضی، آخرین کندل پردازش‌شده، وضعیت HALT و هش فایل‌های پشتیبان ایجاد می‌کند.
فایل‌ها در `observations/` و `observations/backups/` ذخیره می‌شوند.
خروج با کد `2` یعنی هشدار سلامت ثبت شده و **حساب به‌صورت خودکار ریست نمی‌شود**.
پشتیبان هر دیتابیس در زمان خودش سازگار است، اما سه دیتابیس یک تراکنش مشترک ندارند.

این یک ثبت لحظه‌ای است، نه سرویس دائمی یا اثبات پایش ۱۴روزه. بهتر است در هر
نوبت بررسی توسط اپراتور اجرا شود و رخدادهای غیرعادی جداگانه بررسی شوند.
برای جزئیات: [راهنمای عملیات Paper](PAPER_OPERATIONS.md).

## مرحلهٔ دوم: پایش و انتشار سیگنال در MT5

برای فعال‌کردن هم‌زمان پردازش کندل‌های بسته‌شدهٔ M15 و خروجی نمایشگر، این فرمان
را در پوشهٔ `metatr` پس از `git pull` و فعال‌سازی `.venv` اجرا کنید:

```bash
python3 -m metatr.paper_setup \\
  --workspace "$HOME/metatr-state/paper-bip" \\
  --start --confirm-paper \\
  --display-output-dir "$HOME/Library/Application Support/net.metaquotes.wine.metatrader5/drive_c/users/user/AppData/Roaming/MetaQuotes/Terminal/Common/Files"
```

برنامه در همان ترمینال، هر ۳۰ ثانیه منبع عمومی Coinbase را بررسی می‌کند؛ فقط
کندل‌های بسته‌شدهٔ جدید M15 پردازش می‌شوند. این قابلیت فقط تا پایان جلسهٔ
تأییدشده توسط API معتبر است؛ جلسات بعدی خودکار حدس زده نمی‌شوند (Issue #44).

خروجی MT5 یک **سیگنال پژوهشی شبیه‌سازی‌شده** است، نه سفارش اجراشده. اگر ریسک
آن را رد کرده باشد، به‌صورت `NO_TRADE` نمایش داده می‌شود. دفتر سفارش‌ها و
سودوزیان فرضی همچنان در گزارش Paper باقی می‌ماند. تأیید نسخهٔ بومی Wine جداست.

از این نسخه به بعد، آغاز پایش، بسته‌شدن کندل جدید و رخداد HALT موجب ثبت یک
گزارش شواهد خودکار در `observations/` می‌شود. هر گزارش صرفاً وضعیت همان لحظه
را نشان می‌دهد و به‌تنهایی اثبات پایش ۱۴روزه نیست.

برای گزارش تجمیعی روزانه و خطاها:

```bash
python3 -m metatr.paper_monitor_report --workspace "$HOME/metatr-state/paper-bip"
```

آمار این ابزار، تعداد مشاهدات واقعی سیستم و فاصلهٔ بین آن‌هاست، نه درصد
آپ‌تایم. زمان‌های آزمایشی واردشده با `--now-utc` از آمار پایش واقعی حذف
می‌شوند. برای بازیابی پس از خطا، ابتدا علت HALT را بررسی کنید؛ ریست خودکار
فعال نشده است.
